# vss workspace audit

Audit date: November 6, 2026 (America/Edmonton).
Audited commit: `4e6da1dfe64487e39b9024f3ac102da0738a78ae`.
Status: all findings are fixed (November 7, 2026). The ten findings and the
input validation observation were fixed in `eb28b25`, and the follow-up
finding in `8897a23`. They were open at the audited revision.

Follow-up recorded November 7, 2026: `eb28b25` only partially fixed the
audit-log host-write finding, because directory creation could still follow
a planted symlink. See [the follow-up finding](#follow-up-audit-log-directory-creation-still-follows-symlinks),
fixed the same day in `8897a23`.

The audit covered the source, tests, public guarantees, and dependencies of
`vssb` and `vssr`. It found five P1 findings involving filesystem access,
host writes, resource enforcement, and host lifecycle, plus five P2
correctness findings. P1 denotes high priority; P2 denotes medium priority.
The filesystem and resource findings warrant attention before relying on
this revision for unattended execution of untrusted programs.

Evidence below distinguishes reproduced behavior from consequences inferred
from source review. CLI runtime verification remains incomplete because the
command sandbox blocked setup. No fixes were applied during the audit.

## Findings

### P1 Writable directory aliases bypass source checks

Explicit writable roots are collected as lexical paths, while bind sources
are later canonicalized. The symlink guard compares source paths against
those lexical roots, so an alias and the real path of the same writable
directory can receive different treatment.

A temporary fixture used `alias -> real` and a planted symlink inside
`real/work` pointing to a separate sentinel directory. With
`rw = [".../alias/work:/work"]` and
`ro = [".../real/work/planted:/exposed"]`, the dry run succeeded and resolved
`/exposed` to the sentinel directory. Using `.../real/work` as the writable
source instead caused the expected refusal with exit 125.

An earlier sandbox run able to plant the symlink can therefore cause a later
run to expose host paths outside the intended writable directory.

Sources: [writable root collection](../../vssr/src/policy.rs#L412) and
[source resolution](../../vssr/src/policy.rs#L761).

### P1 Mount sources can change after validation

Mount sources are canonicalized and stored as path strings. After cloning,
the child reopens those strings with `open_tree`, following symlinks. A
concurrent sandbox with access to a source's containing directory can
replace a checked entry between validation and opening, redirecting the
bind to another host path. The resulting bind receives the configured
read or write permissions.

This finding comes from source review; a concurrent race exploit was not
run. The [Linux open_tree manual](https://man7.org/linux/man-pages/man2/open_tree.2.html)
documents the path lookup behavior and the separate flag for refusing to
dereference a final symlink. The implementation does not pin the validated
source with a descriptor before this later lookup.

Sources: [canonicalization](../../vssb/src/prepare.rs#L217),
[prepared source strings](../../vssb/src/prepare.rs#L345), and
[child source lookup](../../vssb/src/mounts.rs#L196).

### P1 Audit log symlinks redirect host writes

The supervisor opens the audit log for append and follows symlinks. When
the configured log is inside a directory writable by the sandbox, an
earlier run can replace the log with a link to a file outside the allowed
filesystem view. The next supervisor run appends audit records to that
target with the host user's permissions.

A temporary fixture reproduced this by linking a project's `audit.jsonl`
to an unrelated sentinel file outside the project. Calling `Audit::open`
and recording an event appended JSON to the sentinel. This permits host
file corruption when the log path or its parent directories can be
tampered with.

Source: [audit log opening](../../vssr/src/audit.rs#L21).

### P1 Failed cgroup writes can be reported as enforced

Writing cgroup limits discards errors. The subsequent enforcement check
only tests whether a finite value exists, rather than whether that value
satisfies the requested budget. It also omits verification that swap is
disabled.

A harness using read-only mock controller files requested 64 MiB, one CPU,
and four tasks. All three limits were reported as enforced while the files
still contained 1 GiB, eight CPUs, and 4,096 tasks; `memory.swap.max`
remained `max`. No real cgroup controller files were changed by this
reproduction.

For `Cgroup::Join`, a failed update to an existing finite limit can therefore
silently leave a much larger budget in effect, including in strict mode.
The separate controller values and swap limit are defined in the
[kernel cgroup v2 documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html).

Sources: [limit writes](../../vssb/src/cgroup.rs#L14),
[enforcement checks](../../vssb/src/cgroup.rs#L38), and
[strict mode decision](../../vssb/src/spawn.rs#L195).

### P1 Closed stdin can expose the control endpoint

If descriptor 0 is closed, preparation can allocate the parent control
socket endpoint there. The later `Stdio::Inherit` check sees a valid
descriptor and treats that endpoint as stdin. Init's descriptor cleanup
skips descriptors 0 through 2.

A harness confirmed this before cloning: the parent control descriptor and
the program's stdin source were both 0, while the child control endpoint
was 3. From the child code, init retains a copy of the parent endpoint,
preventing the expected EOF when the host process dies. The complete host
death scenario was not executed for this case.

Sources: [control socket allocation and stdio mapping](../../vssb/src/prepare.rs#L405)
and [init descriptor cleanup](../../vssb/src/child.rs#L94).

### P2 Passed descriptors can overwrite the setup status pipe

Passed descriptor targets are not reserved against the internal status
pipe. Preparation reproduced a layout where both the status write
descriptor and a `pass_fd` target were 7. The program's `dup3` loop then
overwrites the status descriptor before the remaining setup and exec steps.

The parent can mistake the resulting EOF for successful exec, while a
later setup or exec failure writes its report to the passed descriptor.
The overlap was reproduced before cloning; the resulting spawn behavior
was established by source review.

Sources: [descriptor preparation](../../vssb/src/prepare.rs#L410),
[descriptor replacement](../../vssb/src/child.rs#L365), and
[EOF interpreted as exec success](../../vssb/src/spawn.rs#L161).

### P2 Sandbox symlinks can be created in host directories

The `Mount::symlink` branch checks and opens the parent directory, then
calls `symlinkat` without checking whether the final entry may be created
there. Under an existing writable bind, this creates the symlink in the
host directory, violating the stated invariant that mount setup never
creates entries inside a bind mount.

This finding comes from source review. A sandbox execution demonstrating
the host write was not run.

Source: [symlink creation](../../vssb/src/mounts.rs#L258).

### P2 TTY mode discards externally sent interrupt signals

With `--tty`, the supervisor discards every SIGINT and SIGQUIT on the
assumption that the terminal already delivered it to the program. It does
not check the signal's origin. An interrupt sent directly to the supervisor
by another program is therefore dropped, breaking cancellation through
that interface.

This finding comes from source review. The library's init loop already
distinguishes terminal signals using `ssi_code`, but the CLI forwarding
loop does not.

Sources: [CLI forwarding](../../vssr/src/main.rs#L378) and
[init terminal signal handling](../../vssb/src/child.rs#L295).

### P2 Oversized duration input panics

Duration parsing checks that the input is finite and positive, then uses
the panicking `Duration::from_secs_f64` conversion without checking its
representable range or the result of multiplying by the unit.

Running `vssr run --timeout 1e300 --dry-run -- true` reproduced a panic and
exit 101 instead of a configuration error. This reproduction did not start
a sandbox.

Source: [duration conversion](../../vssr/src/util.rs#L18).

### P2 A one task PID limit permits two tasks through the fallback

The public PID limit counts init. The PID namespace fallback clamps
`pid_max` to at least 301, even when `pids = 1`. That leaves PID 1 for init
and PID 300 for the program, permitting two tasks while reporting the
requested limit as enforced through the PID namespace.

This finding comes from source review; the one task boundary was not
tested through sandbox execution.

Sources: [PID maximum calculation](../../vssb/src/prepare.rs#L331) and
[public limit semantics](../../vssb/src/config.rs#L131).

## Additional input validation observation

Passing `i32::MAX` as a `Command::pass_fd` target reproduced an integer
overflow panic in a debug build while computing `fd_base`, before cloning.
The target validation only rejects descriptors below 3. This observation
is separate from the ten prioritized findings above.

Source: [descriptor target bounds](../../vssb/src/prepare.rs#L441).

## Follow-up: audit-log directory creation still follows symlinks

Recorded: November 7, 2026 (America/Edmonton).
Verified fix commit: `eb28b250d910a8a889560384ef0d8d60c7bb0544`.
Status: fixed in `8897a23` (see [Fix](#fix)). When this was recorded, the
original P1 audit-log host-write finding was only partially fixed, and the
affected implementation was unchanged at `80f7a50`.

The fix blocks appending through a symlink used as the log file and opens
an existing, checked parent directory with `openat2(RESOLVE_NO_SYMLINKS)`.
However, when `resolve_guarded` encounters a missing path component,
`open_log` first calls `std::fs::create_dir_all(parent)` on the original
path. That operation can follow symlinks and runs before the parent is
pinned with a descriptor. A later refusal does not undo directories it
already created outside the allowed filesystem view.

A bounded fixture reproduced this without a race. Inside a writable
`project`, `logs` was a symlink to a separate `outside` directory. The
configured log path was `missing/../logs/created-outside/audit.jsonl`, with
`missing` initially absent. The first guarded lookup stopped at `missing`;
`create_dir_all` then created `missing` and followed `logs`, creating
`outside/created-outside`. The second guarded lookup refused the symlink,
and the CLI exited 125, after the unauthorized directory creation. No log
file was appended or created outside the project in this reproduction.

Run from the workspace root after building `target/debug/vssr`:

```python
import pathlib
import subprocess
import tempfile

binary = (pathlib.Path.cwd() / "target/debug/vssr").resolve()
with tempfile.TemporaryDirectory(prefix="vss-audit-directory-repro-") as tmp:
    base = pathlib.Path(tmp)
    project, outside = base / "project", base / "outside"
    project.mkdir()
    outside.mkdir()
    (project / "logs").symlink_to(outside, target_is_directory=True)
    result = subprocess.run(
        [str(binary), "run", "--no-detect", "--audit-log",
         "missing/../logs/created-outside/audit.jsonl", "--", "true"],
        cwd=project, capture_output=True, text=True, timeout=5,
    )
    print("exit:", result.returncode)
    print("outside directory created:", (outside / "created-outside").is_dir())
    print(result.stderr.strip())
```

Observed: exit 125, `outside directory created: True`, and an error saying
`refusing to follow the symlink`. All fixture writes were under a temporary
directory, removed afterwards; audit opening failed before sandbox spawn.

The ordinary path `logs/new/audit.jsonl` was also checked with a controlled
interleaving: an `LD_PRELOAD` wrapper planted `project/logs -> outside` at
the first `mkdir`, after guarded resolution had found `logs` missing. It
created `outside/new`, then exited 125 with the same refusal. This
demonstrates the unsafe interleaving; a live concurrent sandbox exploit
was not run for this follow-up.

Directory creation needs to operate relative to pinned directory
descriptors, refusing symlinks while opening each component and creating
missing components with `mkdirat`. Rechecking the full path after
`create_dir_all` cannot prevent these host writes.

Sources: [missing-component handling](../../vssr/src/util.rs#L148),
[unguarded directory creation](../../vssr/src/audit.rs#L60), and
[later directory pinning](../../vssr/src/audit.rs#L64).

### Fix

Fixed November 7, 2026. `open_log` no longer creates directories by path.
`resolve_guarded_prefix` resolves the part of the directory that exists,
which is pinned with `openat2(RESOLVE_NO_SYMLINKS)`; each missing component
is then created with `mkdirat` and opened from its parent's descriptor
with `RESOLVE_NO_SYMLINKS`, so a symlink planted before or during this is
refused rather than followed. A `..` after a missing component is refused
before anything is created. The reproduction above now exits 125 with
nothing created (`missing` included), and `logs/new/audit.jsonl` is refused
the same way.

Tests: `audit::tests::creates_directories_without_following_symlinks`
(this reproduction), `audit::tests::creating_directories_races_a_planted_symlink`
(a thread planting `logs -> outside` while the log is opened in
`logs/new`; both fail with the old code), and in `integration.sh` the
reproduction plus a fresh `logs/new$i/` in the swapping-sandbox race.
